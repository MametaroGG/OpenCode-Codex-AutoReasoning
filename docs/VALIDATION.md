# 検証結果

実行日: 2026-11-09 / Windows / Node.js v22.21.0。

現行構成の開発用調整は`openai`プロバイダのみ、判定役はLuna専用。非OpenAIでは手動設定時も判定・設定変更を行わない。Haiku判定設定は拒否し、黙ってLunaへ切り替えない。Gemma検証記録は履歴として保存した。旧ローカル判定は比較用に `scripts/baselines/` へ隔離し、実行・配布対象から除外した。既定タイムアウトは15秒。

**実OpenCode 2.2.6で、本体ロード・prompt ID対応・Luna判定・Solへのlow/xhighの最終HTTP送信・HTTP 200・状態RPC・主モデルのusageイベントを確認済み。** 新たなユーザー承認に基づきLuna 2回＋Sol 2回を実行した。[実ホスト検証](LIVE-HOST-VALIDATION.md)に記録。

主なテスト対象:

- Anthropic、Bedrock、Gemini、Vertex、カスタムOpenAI互換接続で設定を保持し、Lunaを呼ばない。手動override時も同じ（モック）。
- context hookのOpenAI限定登録と、非対応プロバイダを二重に保護する早期終了。
- Haiku・Gemma・Geminiの判定設定は生成前に拒否。

- 同一タスクのTTL/LRUキャッシュ、同時重複判定の集約、新しいメッセージ・変更内容での再判定。
- 判定失敗、判定モデル不在、モデル取得失敗時の元設定保持。

- 手動指定、明示variant、既存request override、無効化の優先順位。
- 実ホストが省略時に付ける`default`は自動調整し、カタログに実在する同名variantは保持する回帰テスト。
- 複数セッションの分離、1万タスク実行後の保持上限、同時判定の上限。
- 単体テストでは公式API形状のsetup/context/toolコールバックをモックホストで実行。別途実ホストでも2ターンを確認済み。
- 読み取り専用状態RPCが判定値・判定回数を変えないこと。
- TUIの状態コマンド、ホーム画面案内、エラーの秘匿、重複実行防止、移動・アンロード後の古いダイアログ抑制。
- 部分的な登録失敗時のロールバック、アンロード後に未完了lookupの例外で状態が復活しないこと。
- 判定モデルを別に指定しても、開発用モデル・会話・system instructions・ツールを変更しないこと。
- 外部送信許可なし、モデル不在、元のprompt-hook入力なし、壊れた応答ではモデル呼び出しや設定変更を行わないこと（壊れた応答は呼び出し後の設定変更を防止）。
- 単純な誤字修正も選択した判定モデルに送ること、キャッシュ、手動指定・明示variant時の追加生成回避。
- 展開後ソース・system instructions・コードフェンス・一般的な資格情報を判定プロンプトへ含めないこと、入力の合計文字数上限。
- 同一メッセージIDに対して異なる受付hook入力が競合した場合、敗れた入力を送らず元設定を保持すること。
- モデル呼び出し回数上限、不正応答後も回数を戻さないこと、中止を無視する生成が残っている間の追加モデル呼び出し防止。
- SDKが使用量を返さないモデル呼び出しを、成功・失敗とも0トークンではなくnullとして扱うこと。
- 実モデル評価用データの24件・4段階の均等性、一致率・失敗率・過小評価・再現一致率の集計。

配布テストは初回、未ロックのconsumerで新しいpeer依存が選ばれ、npmキャッシュ不足（ENOTCACHED）で失敗した。既存lockfileを引き継ぐよう変更後に成功。依存ライフサイクルスクリプトは無効、ネットワークも禁止した。配布物は実インストールしたが、OpenCodeホストはモックであり、ネイティブTUIはインポート・描画せずentrypointファイルの存在だけを確認した。

## 依存関係の監査

`npm audit --omit=dev --json`: moderate 24件、high 0、critical 0。終了コード1。

主な経路は公式 `@opencode/plugin@2.2.6` → `@opencode/util` → npm関連依存のglob/minimatch等。監査には推移的な影響先も含まれ、24種類の独立した欠陥を意味するものではない。

- [glob: AbortSignal cancellation bypass](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4)
- [minimatch: potential denial of service](https://github.com/advisories/GHSA-g3hv-75wg-m249)

公式SDKに対する修正版の存在が監査で確認できないため、破壊的な `npm audit fix --force` や未検証の依存overrideは実行しなかった。プラグインはglob/minimatchによるユーザー入力解析やファイル探索を行わないが、依存全体を安全と保証するものではない。SDKの更新時に再監査が必要。

## 未検証

- native TUIでのロード・スラッシュコマンド・ダイアログ描画。RPCルーティング自体は実ホストで確認済み。
- WebSocketの最終送信フレーム、ツール継続・明示variant等の全組合せ。今回の実試験はHTTPの2ターンのみ。
- モデルの幅広い応答時間分布、トークン削減、成果物の品質維持・向上。今回の開発側は実装せずOKと返す通信試験。
- Lunaの実モデル判定は24課題×2回で実測済み。[初回精度検証](ACCURACY.md#初回実測結果)参照。通常の単体テストのモデル応答は引き続きモック。より広い課題・他モデルとの比較、実請求額、使用制限は未検証。
- 実OpenCodeのprompt hook messageIDと送信前user message IDは今回の2件で一致。より広い入力・添付・稼働途中の導入は未検証。対応が取れなければ外部送信せず元設定を維持し、古い会話へ遡及送信しない。
- SDK/サーバーがAbortSignalに応じて外部推論を停止すること。タイムアウトで課金が停止することや請求額の厳密な上限は保証しない。
- 主モデルのusageイベントは実測済み。補助モデルの使用量・主モデルとの正確な費用内訳は未検証。
- 長時間連続稼働時のRSSの安定性。
- GitHub上でのCI・draft作成workflowの実行、公開リポジトリからの配布。準備したworkflowとローカル配布パッケージの検証にとどまる。

グローバル設定・利用先プロジェクト・認証設定は変更していない。初回精度評価のLuna独立生成48回とは別の承認で、実ホスト試験のLuna 2回＋Sol 2回を実行した。Gemma接続試験も別台帳に保存している。課金または利用枠の消費が発生する可能性があり、Lunaの実費はAPIから取得できず不明。詳細・全結果・限界は [ACCURACY.md](ACCURACY.md) と [LIVE-HOST-VALIDATION.md](LIVE-HOST-VALIDATION.md) に記録した。
